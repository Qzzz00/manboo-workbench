# 例程(工作台开的会话,你接着做)

三条例程都是**工作台(插件)按时开一条会话**,第一条 user 消息由代码从固定模板拼出来——不是 Ben 亲口说的,
但内容都是从记忆文件与 `/state` 数出来的事实。你要做的部分写在下面;写权限、读的顺序、commit 规范一律按
`.dsh/skills/记忆/SKILL.md`,本文件不另立规矩。三条共同的边界:**只追加不删、不改 AGENTS.md / docs/记忆/README.md /
两份 SKILL.md、凭据不进任何文件、每次写一次 commit(配了远端就 push,没配只提交)**。

## 开工汇报(第一条消息以三句加一问开头,落款「工作台开工汇报 <日期>」)

那三句是工作台拼的,Ben 已经在收件箱里看到了。你**只回一行「等你定」**——不复述、不总结、不动手、不读文件。
Ben 在这条会话里回答「今天先做哪件」之后,你才按 `.dsh/skills/记忆/SKILL.md` 读记忆、接手那件事。
他没回答之前,这条会话什么都不做。

## 下班例程(第一条消息落款「下班例程 <日期>」)

工作台已经做完 `docs/记忆/下班例程.md` 里机械的几步(第 0 步**收**各家 AI 的记忆、读 `/state`、
覆盖 `docs/记忆/工作台-布局.md|.html`、给每个今天有活动的项目追加一条进展、
更新 `docs/记忆/项目/索引.md`(每一行都补上文件)与 `docs/记忆索引.md`、一次 commit、配了远端就 `git push`),
第一条消息里写着它做了什么、commit 号是多少、推没推成。你只做判断类的那几步:

1. **并第 0 步收来的那几份**(2026-09-26,设计-讨论结论都落进工作台记忆-2026-09-26 §二 5)。
   第一条消息里列着「新增或变了的」文件与指纹(说没有就跳过这一件),**只处理列出来的那几份**。

   **一份一份来,不要攒到最后。** 2026-09-26 那次就是攒到最后的:并到第 23 份时会话断了,
   台账一行没写、并好的 6 个文件一直没提交,第二天同样 59 份还得再读一遍。所以每一份都这么走:
   1. 先在目标文件里搜一下这份的**原件路径**:已经作为依据出现过 = 以前并过了,
      这次**只补台账那一行**,不要再并一遍、不要再写一条重复的观察;
   2. 没出现过才读它 —— 他的喜好习惯 → 用户文件「观察」段;某个项目的事 →
      `docs/记忆/项目/<名>.md` 的「进展 / 风险 / 关键文件」;纯技术备忘 → **不并**,但也算已看过。
      每条**带依据(原件路径)**;
   3. 这一份处理完(含判定「不并」的)**立刻**往那一家的 `来自-<家>/已并入.md` 追加这一行,
      表头就四列:`| 文件 | 指纹 | 日期 | 并到哪 |`(文件写相对 `来自-<家>/` 的路径,指纹照抄消息里那一串);
   4. **每处理完 5 份 commit 一次**(`chore(记忆): 下班例程 <日期> 并入`)。

   **记了的下次就不再列给你** —— 漏记一行等于明天再读一遍同样的内容;反过来,中途断了也不怕:
   下次开会话时清单里只剩没记过的那几份,接着做就行。工作台每 10 分钟还会把记忆目录里
   没提交的改动收尾提交一次,并把每一家的进度刷进 `来自-<家>/来源.md` 顶上那一块。
2. **今天对话里听到的偏好 / 自述** → 用户文件「观察」段追加,带日期与依据(哪条会话)。没听到就不写。
   用户文件叫什么按仓库里现有的那份算(`docs/记忆/用户-*.md`,通常是 `用户-<他的称呼>.md`);第一条消息里写着路径。
3. **矛盾**:读 `docs/记忆/项目/索引.md` 与今天动过的项目文件,对照 `docs/决策记录.md` 最新「已拍板」;
   说法打架的地方**在回话里指出来**,不自行修文。
4. **待拍板**:今天出现的、该由 Ben 定的事(一句话/阶段/目标的改动、新的取舍)→ `docs/决策记录.md` 追加「待拍板」条目。
5. 偏好与待拍板那几步写完再 commit 一次(`chore(记忆): 下班例程 <日期> 观察`;第 1 件那几笔另算)。
   **工作台那一笔已经由代码提交并推过了**,你只推**你自己这几笔**:配了远端就 `git push`,
   没配就只提交、不推;推不上去在回话里说。
6. **回 Ben 三行**:今天记住了什么、有什么矛盾、有什么待拍板。三行就是三行;
   第一行末尾带一句「今天从各家 AI 收了 N 份、并进 M 条」。

不做:不重做工作台已经做过的步骤、不改「进展」里已有的条目、不动 `~/.dsh`、不删任何文件。

## 知识 lint(第一条消息落款「每周知识 lint <日期>」)

只提议,不动手。通读 `docs/记忆索引.md` 与近 7 天的 `docs/交接-*.md`,**只写一份** `docs/交接-<MMDD>-知识lint.md`,三节:

1. **可归档的交接**:哪些交接的结论已经进了决策记录 / 能力清单 / 记忆文件,可以标「已吸收」(列文件名与吸收到哪里)。
2. **该进决策记录的结论**:交接里出现、但决策记录里没有的拍板或取舍(引用原文位置,拟一条「待拍板」的写法,不直接写进决策记录)。
3. **前后矛盾**:文件之间说法打架的地方(各引一处),以及你建议以哪一份为准——建议而已,由 Ben 定。

写完 commit 一次(`chore(记忆): 知识 lint <日期>`);这一条代码没有替你提交,所以这一笔由你推:
配了远端就 `git push`,没配就只提交、不推。回三行摘要(各节几条)。
**不改任何别的文件**:不改决策记录、不改交接、不改记忆文件、不删东西。这份交接本身进收件箱作为一条待拍板事项,Ben 点头后才有人动手。

## 排期怎么记(交代排期或多项拆解任务时)

当他交代排期、多项待办计划或拆解任务时:

1. **先建目标**:标题(一句话说清要达成什么)、为了什么(why)、截止时间(due)。
2. **再建卡**:
   - 缺省放在「待排」(`backlog`),不进待办,防止被后台直接派出去;
   - 设类型:会议(`meeting`)、研发与设计(`dev`)、内容与推广(`content`)、经营与其他(`routine`);
   - 设起止时间(start / end);
   - 验收标准 1–3 条短句(`acceptance`);
   - 来源留痕(`from`);
   - 挂上刚才建的目标(`goal_id`);
   - 选定负责人(`assignee`:名片 `agent:<id>` 如小K、C老大,或家名/人)。
3. **全部建完后再汇报一句**:「排好了,N 个目标 M 张卡,都在待排。」不边建边吵他。
