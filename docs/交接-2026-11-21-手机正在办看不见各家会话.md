# 交接：手机「正在办」一直 0 事项、看不见电脑端 agent 进展(2026-11-21)

维护者报：事务官工作台手机端「正在办」一直处于 0 事项，无法监测到电脑端 agent 的具体工作进展。

## 查到的事实(本机实时 /state 验证)

- 当时登记表里真有一条 Kimi 会话在跑(`70396eb6…`,标题「事务官工作台手机端监测异常」),没挂在任何事项上；
- `/state.running` = `{scope:'classified_business_tasks', observed_count:0, items:[], excluded:[]}`,`count` **缺席**;
- `execution.complete` = `false` —— 8 张 11-16~11-19 的旧卡(4 张 confirm 无回执、1 张 done、3 张 canceled 里没收场的几张)的 Codex 来源文件早没了,来源永远 `unknown`,闸门要求「在列的每张卡来源全部可判定」,于是 `complete` 永远假、`running.count` 永远发不出来;
- 把实时 /state 喂给手机端模型复现:首页「正在办」卡 `count` 缺席、0 行、空文案「业务任务总数未知,已观测 0 件」—— 正是维护者看到的样子。

## 两个根因与修法

**① 手机首页卡把「各家在跑的会话」整段丢了**(`butler-app/src/stage/stageCardsModel.ts` `doingCard`)。
10-28 断点④改成分类业务范围后,`state.running` 存在时卡面只画业务事项行,`externalRunning` 那几行算出来却被丢弃。这张卡的契约(文件头那张表)一直是「在办事项 + 各家客户端在跑、没挂事项的会话」,电脑首页球周围那几张(`butlerSceneModel.externalRunningSessions`)也一直在 —— 只有手机首页空了。
修:卡面 = 业务事项行 + 各家在跑会话行(去重照旧,挂在事项上的不重复列);那颗数 = 公共业务数 + 卡面列着的会话数(09-25 卡 V 的老规矩:列着的与数着的要一致);业务总数没核完(闸门未过)时不画数,会话行照列、不背「业务总数未知」。

**② 完整性闸门被收场旧卡永久卡死**(`workbench-plugin/src/server/executionState.ts` `executionOverview`)。
原豁免只给「unclassified + state unknown + 卡收场(done / confirm / blocked)」三张条件都齐的卡;业务的 done / confirm 卡不在豁免里,永远 `unknown` 的旧来源把闸门卡死。
修(分档,宽严有别):
- **done / confirm** 的卡:活已收尾,与「今天在跑几件」无关,没目击到在跑来源就豁免,不分角色(业务卡是这次新增的豁免;目击到 `running` 的照旧留在闸门里 —— 「卡片 done 不推断原生会话结束」那条用例原样通过);
- **blocked** 的卡:未分类卡照老规矩豁免;**业务卡保持保守** —— `execution-facts-http` 有一条钉住的用例(双来源旧阻塞、较晚来源失联 → 仍标未知、总数缺席、事项不被重写),第一次收窄时撞上了它,按其口径把业务受阻卡留在闸门里。
修完用实时任务账验证:`complete` 转真,`running.count` 发布为 0(此刻确实没有业务事项在跑,是实话),手机那颗数随之 = 0 + 1 条在跑会话 = 1。

## 碰了哪条接缝

- **8791 接口契约**:`/state.execution.complete` 的判定放宽(接缝主人:8791 接口)。`count` 的语义没变(仍是「确认在跑的业务事项数」),只是从「永远缺席」恢复为「可发布」。
- 消费方对照:`butler-app` 那份 `RunningView` 只加可选字段的三方契约未动;桌面消费方(`businessExecutionModel` / `butlerSceneModel` / `orbCell` / `BusinessExecution` / `DockTabBar`)全部读过,`count` 恢复发布后它们各自回原设计行为,无需改。

## 查过的兄弟路

- 手机事项页「各家正在办」(`InboxPage` → `externalRunning`):本来就没坏,实时数据验证能列出在跑会话;
- 手机球在办信号(`swarm/orbState.ts`):`count` 缺席时退回登记表扫描;闸门放开后走发布的 `count`,与电脑 `orbCellOf`(`count ?? observed_count`)同口径,两端一致;
- 电脑舞台各家会话卡、球下「执行 n」、汇报条(`butlerReportLine`):读同一 `running.count`,闸门放开后恢复;
- 窗口槽各家角标(`DockTabBar`):读登记表,不受影响;`/collab/runs` 与协作区在跑列:读任务日志,不受影响;
- 来电 / 去电、捎话 / 派活 / 替她答:未涉及。

## 没做什么

- **没重启 DSH、没碰 `~/.dsh`**(发版与重启归维护者):修复在源码上,要维护者合并发版后,8791 与手机端才生效;
- `observed_count` 口径未改(仍只数分类业务项,不含各家散会话);
- 手机端全量有 7 个既有失败(`clientKey` 一字不差、`deckRunBadge` 逐行相同、`inboxDetail` 取消这件、`phoneNavLayers` 通话返回 ×3、`StagePage` 引导横幅),改动前后逐一核对过,与本次无关,留给各自的卡。
