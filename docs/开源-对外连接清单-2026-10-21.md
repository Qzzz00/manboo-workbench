# 对外连接清单:它到底连了哪里

日期:2026-10-21。读者:拿到开发仓的工程师与自己部署的人。回答三个问题:每条连接干什么、默认连到哪、怎么改或关。

**先说结论**:本机之外,事务官座机默认连这几类地方 ——
① 我们自己的中转(`api.aibooo.cn`:模型中转、账号、通话凭据、更新清单、出错报告);
② LiveKit 房间(`lk.aibooo.cn`,由中转下发或本机 `channel.json`);
③ Aiboo 云(`your-aiboo-host:3456`,今晨快报、AiDJ 电台、展示台的音乐 / 歌词 / 角色;**本仓库没有它的后端源码**);
④ 你自己填 Key 的模型与语音服务(DeepSeek、火山、百炼、MiniMax 等);
⑤ 几个公开接口(AIHOT 日报、天气、额度查询)。
资料与配置都在本机;调用模型、语音、搜索和中转时会把相关内容发出去,**不是完全离线**。

**10-21 起(局域网 M7)中转地址不写在源码里**:开源仓库按 README 构建出来的是「零服务器」那一档,① 和更新清单都没有;
我们自己的发版构建在构建时注入。安装与能做什么见 [安装-零服务器](安装-零服务器.md)。

## 两档构建各带什么

构建时由 `workbench-plugin/scripts/build-endpoints.mjs` 定,编进插件与安装器内核(`src/buildEndpoints.ts` 读);手机包由
`butler-app/scripts/build-relay.mjs` 按同一条规矩定中转那一个:环境变量 `WORKBENCH_BUILD_RELAY_URL` / `WORKBENCH_BUILD_UPDATE_URL`
压过 `deploy/release-endpoints.env`(设成空也算),两样都没有就是空。听筒不经构建,服务文件里 `WORKBENCH_RELAY` 缺省就是空。

| | 开源构建(开发仓按 README 构建) | 我们的发版构建(内部仓,`publish-update.sh` / `build-installer.sh`) |
|---|---|---|
| 构建档 | 没有(`deploy/release-endpoints.env` 导出开发仓时剥掉) | `deploy/release-endpoints.env` |
| 中转缺省(`model.json` 没填 `relay_url` 时) | 空 = 这台没接中转 | `https://api.aibooo.cn` |
| 热更新清单缺省 | 空 = 不查更新 | `https://api.aibooo.cn/updates/latest.json` |
| 模型缺省 | 用自己的 DeepSeek Key | 用工作台提供的服务(中转) |
| 账号 | 本机账号,只在这台电脑上 | 注册 / 登录走中转,连不上退回本机 |
| 通话 | 本机房间(在家) | 本机房间 + 云房间(出门) |
| 搜索 | 填了博查 Key 直连,没填说「搜索没配」 | 填了博查 Key 直连,没填走中转 |
| 打包时的核对 | 产物的代码里一个 `aibooo.cn` 地址都没有 | 产物里两个地址各编进一次;真推时更新清单必须正是 `<--base-url>/latest.json` |

自建中转的人用开源构建也行:中转地址写进 `model.json` 的 `relay_url`,更新清单写进 `endpoints.json` 的 `update_manifest_url`,压过构建缺省。
`/state.relay_configured`、`/channel/route` 里 `relay` 那一格缺不缺席、`/account.relay_configured`,三处说的是同一件事:这台接没接中转。

## 配置放在哪

| 位置 | 管什么 | 读法 |
|---|---|---|
| `~/.dsh/workbench/model.json` | `relay_url`(中转地址;没填 = 构建缺省,开源构建是空)、`mode`(`relay` 走中转 / `own` 用自己的 DeepSeek Key;没有中转地址时一律按 `own`) | 插件、通话组件、DSH 三处共用;改完在设置里切一次模型或重启 |
| `~/.dsh/workbench/credentials.json` | 各家的 Key:`deepseek`、**10-21 新增** `bocha`(博查搜索)、`volc_asr_app_id` + `volc_asr_access_token`(火山识别) | 设置 › 各家的密钥与登录;只回「配了没有」 |
| `deploy/release-endpoints.env`(只在内部仓) | 我们发版构建的中转与更新清单地址、两份部署脚本的域名 | 构建时读,不进开发仓 |
| `~/.dsh/workbench/endpoints.json` | **10-21 新增**:`aiboo_url`、`aihot_url`、`update_manifest_url`;**10-23 增**:`viz_cdn_url`(图谱页绘图组件下载地址)、`uv_bootstrap_url`(uv 官方安装脚本下载地址);任一项写 `"off"` = 不连 | 插件启动时读一次,改了重启 DSH |
| `~/.dsh/workbench/channel.json` | LiveKit:`url`、`http_url`、`api_key`、`api_secret`、`room` | 有本机 key/secret 就不向中转要凭据 |
| `~/.dsh/workbench/aidj-config.json` | AiDJ 电台:`enabled`(默认关)、`base_url` | 手机上那个开关写它 |
| `~/.dsh/workbench/feed-config.json` | 资讯:`enabled`、`aihot` 等开关 | 设置里改 |
| `~/.dsh/workbench/app.json` | `diag_report`:出错是否自动报给开发者(缺席 = 开) | 设置里改 |
| `~/.dsh/workbench/butler.json` | 事务官后端:**10-21 新增** `endpoints`:`volc_openspeech_url`、`volc_openapi_host`、`volc_rtc_host` | 后端启动时读一次 |
| 事务官后端管理页里的语音 / 通话「提供方」 | 各家 Key;MiniMax、百炼的 `apiUrl` | 存在本机 sqlite |
| 中转服务器的环境变量 | `RELAY_UPSTREAM_URL`、`RELAY_SEARCH_URL` 等(见下) | 自建中转时用 |

环境变量能压过文件(给测试与灰度用):插件 `WORKBENCH_AIBOO_URL` / `WORKBENCH_AIHOT_URL` / `WORKBENCH_UPDATE_URL`、
后端 `BUTLER_VOLC_OPENSPEECH_URL` / `BUTLER_VOLC_OPENAPI_HOST` / `BUTLER_VOLC_RTC_HOST`。DSH 进程的环境变量不好改,日常改文件。

## 只在部署脚本里

`deploy/publish-update.sh`(`--base-url`、`--host`)、`deploy/aliyun-relay-setup.sh`(`RELAY_DOMAIN`)、
`deploy/aliyun-livekit-setup.sh`(`LIVEKIT_DOMAIN`)只在维护者自己的机器上跑,用来往服务器上发版与装服务。

## 已知没做的

- 手机端登录页还没按「没接中转」藏起来(卡 M4 接:手机包 `DEFAULT_RELAY_URL === ''`,或 `/channel/route` 里 `relay` 整格缺席)。

协作区可按需连接用户明确配对的私网 IPv4/端口（无缺省地址），复用设备配对服务发送同项目消息和报告。成员地址由本机 `/collab/lan/connect` 配置，只允许私网及回环地址，不扫描网络、不走 relay。频道记录在本机任务账；投递时向所选对端发送相关消息、项目标识和稳定成员身份。
