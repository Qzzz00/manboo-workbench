# 第三方依赖许可清单

日期:2026-10-21。基线:本分支(`main@639bf184` 之后的开源整理)。读者:拿到开发仓、想知道「这个仓库带了谁的代码、按什么许可」的工程师。

## 怎么来的

八个 Node 工程逐个 `pnpm install --frozen-lockfile` 之后跑 `pnpm licenses list --json`(全部依赖)与 `--prod`(只看生产依赖),
按 SPDX 许可归类。**MIT、MIT-0、Apache-2.0、ISC、BSD-2/3-Clause、0BSD 视为宽松许可,只计数**;其余每一个列出来并给处理结论。

复现:在任一工程目录里 `pnpm install --frozen-lockfile && pnpm licenses list --prod`。

「生产」= 会随安装包、热更新或手机 App 发到用户手上的依赖。**注意插件是例外**:`workbench-plugin` 用 tsdown 把依赖打进
`dist/` 的一两个文件里,`package.json` 里全是 devDependencies,所以它的「开发依赖」里被 import 的那部分其实随包分发。

## 运行时按需下载,不进安装包(2026-10-23 新增)

「图谱」格(`workbench-plugin/src/server/graphify.ts`)在用户点「装上 / 重建图谱」时,经 uv 从 PyPI 装
**graphifyy 0.1.14**(MIT;包名双 y,命令不叫 extract 也不叫 --version,走 Python API)到本机 uv 缓存,
版本钉死在源码的 `GRAPHIFY_SPEC` 里。这一层**不经我们的构建与安装包分发**:开源仓和发版包都不带它,
用户不点那两颗键,机器上一份字节都不会下载。

- 直接依赖:graphifyy 0.1.14(MIT)+ tree-sitter ×15(MIT)、networkx(BSD-3-Clause)、graspologic(MIT)等,全宽松。
- 传递依赖里有一个要单独说:**gensim 4.4.0(LGPL-2.1-only)**,经 graspologic 拉入。它只在运行时被
  Python import 进内存用:我们不分发、不链接、不改它,义务落在分发方,而我们不是分发方。真到
  「随安装包预装图谱环境」那一天,按 LGPL 重新评估一遍再动。
- 用途边界:这一格只跑 tree-sitter AST 结构解析(只收代码文件),**语义那一路(要模型)不从这条链路启动、
  也不从这台机器往外发内容**。

## 维护

加依赖时跑一次 `pnpm licenses list --prod`,出现上表以外的非宽松许可就在这里补一行结论;
`channel-worker` 换 LiveKit / sharp 版本时同步 `channel-worker/THIRD_PARTY_NOTICES.md` 里的版本号。

2026-10-24 协作区 LAN 消息使用 Node 内置 HTTP/fetch、crypto 和文件 API，复用现有设备配对；未新增第三方依赖或许可。
