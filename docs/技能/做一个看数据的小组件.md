# 技能:做一个看数据的小组件

> 这份是**事务官的技能**。工作台会把它整段写进 `~/.dsh/AGENTS.md` 的
> `<!-- 引导:做一个看数据的小组件:开始 -->` … `<!-- 引导:做一个看数据的小组件:结束 -->` 标记段里,
> 段外一个字不动。**两种模板下都写** —— 想在工作台上看一个后台的数,跟他做产品还是做运营无关。
> 依据:`docs/设计-用户自己的那一层-2026-09-23.md`(每人一层,本体只有一个;用户层由我动手写,但有边界、要验、能撤)。

## 什么时候用这一条

他说的是「想在工作台上看某个后台的数据」,而那个后台工作台**还没有**现成的格子:

- 「我在小红书开店了,想看店铺的数据」
- 「把抖音的后台数据也放上来」
- 「每天帮我看一眼千川的消耗」

判据:他要的是**一个持续更新的数字格子**,数据来自**他自己登着的某个网页后台**。
小红书**创作者中心**的八个数工作台已经有「数据复盘」那一格,那不走这一条。

## 我做的是「用户层」里的东西,不改工作台本体

这条路上会产生两样东西,都在他机器上、都能撤:
一个**采集器**(一份定义,工作台照它去那一页把看得见的字读回来)+ 一个**小组件**(一个小网页,把字变成数画出来)。
我**不写工作台的代码**,也不直接写 `~/.dsh`(采集器定义走 `/collector/add` 由工作台落进用户层,我不手写那份文件)。

## 输入

1. 他那句话(要看什么);
2. **那一页的网址** —— 我问他从浏览器地址栏复制给我。**我不猜网址、不自己去搜**;
3. 他想看哪几个数(可以等采回来看到页面文字再一起定)。

## 步骤

### ① 建采集器

```
POST /collector/add { "name": "店铺", "url": "<他给的网址>", "note": "<他那句话>" }
```

- `name` 是他叫它的名字(≤24 字,不带 `/`);同名已有就换一个或先撤掉;
- 只认 `https://` 开头;网址里不许带账号密码;
- 不传 `profile`,工作台会给这个采集器**单独一个登录档案**(不与创作者后台串号)。

### ② 让他登录

```
POST /collector/login { "name": "店铺" }
```

工作台会弹一个专用浏览器窗口开到那一页。**他自己登录,我不填任何东西、不问账号密码。**
登好了让他说一声。

### ③ 采一次,看看采到了什么

```
POST /collector/run { "name": "店铺" }
```

- 成了回 `{ ok:true, record:{ status:'ok', chars } }`,文字落在 `<工作目录>/数据/店铺/最新.txt`;
- `logged_out` / `captcha` / `blocked` → **停下,把 `error` 那句原话念给他**。不重试、不换地址、不替他过验证码;
- 「两次之间至少隔 10 分钟」「今天已经采过 4 次」→ 如实说,等;
- `window_closed` → 那个窗口没开着,回到 ②。

采成之后我**读 `最新.txt`**,看清页面上有哪几个数、各叫什么、长什么样(比如「成交金额 ¥1,234.00」)。
**页面上没有的数不能有**:他要的数那一页没有,就告诉他那一页没有,问他换哪一页。

### ④ 做小组件(走「开发一个小工具」那条老路,不自己写文件)

把需求**预填**进那条链路,由他点确认、再由工作台**派给能写代码的那一家**做
(2026-10-01,设计 C2:我只写交代 + 验收,网页不由我写):

```
POST /butler/item { "kind": "dev_tool", "text": "我想在窗口槽里放一个小工具:<名字>,读 GET /module/data?name=店铺,从 text 里取出 <数 A>、<数 B>、<数 C>(页面上写作「…」),画成三个大数字,底下写「采于 <at>」;text 里找不到这几个数时明说「这一份读不懂了,最后一次能读的是 <at>」,不编数。" }
```

- 需求里要写清:**取哪几个数、页面上原文长什么样**(我在 ③ 看到的);
- 小组件只能用规范里那九条接口;`GET /module/data` 是第七条;
- 他点了确认之后由**派出去的那一家**去做,做好窗位叠自己多一个标签。**我不替他点确认。**
  一家都派不出去时工作台如实回一句「这台电脑上没有能写代码的 Agent」——
  **把那句话原样念给他**,不自己顶上来写。

### ⑤ 让它每天更新

不用我做:工作台早报前会把每个采集器各采一次(过闸的才采)。他手点也可以(③ 那条)。

### ⑥ 回看与撤

- 下班例程里若问到「店铺那一格用了没」,把他的话记下;
- 他说不要了:`POST /collector/remove { "name": "店铺" }`(定义进回收站、采过的数据不删),小组件在窗位叠那个标签上走回收。

## 固定产物(工作台写的,不是我亲手落的)

- `~/.dsh/workbench/用户层/采集器/<采集器名>.json` —— 采集器定义(`/collector/add` 落;撤了搬进 `用户层/采集器/.trash/`);
- `<工作目录>/数据/<采集器名>/最新.txt` —— 最近一次采成的页面文字(`/collector/run` 落;另有当天一份与 `采集记录.jsonl`);
- 小组件在 `~/.dsh/workbench/用户层/网页小组件/<id>/`,由「开发一个小工具」那条路上**派出去的那一家**落。

## 不做的

- **不猜网址、不自己搜后台地址。** 网址只从他手里来。
- **不填任何表单、不点任何按钮、不过验证码。** 采集器只读页面上看得见的字。
- **不在工作台本体里写解析**:把字变成数是小组件自己的事。
- **不编数。** 页面上没有的数,小组件上就没有;读不懂就明说。
- **不直接写 `~/.dsh`、不写工作台源码。** 采集器定义经 `/collector/add` 由工作台落进用户层;我不手写用户层里的文件。
