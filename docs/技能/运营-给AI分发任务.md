# 技能:给 AI 分发任务

> 这份是**事务官的技能**。工作台会在**自媒体运营模板**下把它整段写进 `~/.dsh/AGENTS.md` 的
> `<!-- 引导:运营-给AI分发任务:开始 -->` … `<!-- 引导:运营-给AI分发任务:结束 -->` 标记段里,
> 段外一个字不动。做产品模板下**不写**。
>
> 正文里的 `{{工作台地址}}` 是**占位**,不是要照着敲的字:写进 `~/.dsh/AGENTS.md` 时工作台换成
> **这台服务真在听的地址**(回环 + 真端口,按 `WORKBENCH_PORT` 算)。以前这里写死过一个端口,
> 于是灰度实例里的事务官照它去派活 —— 派的是生产(2026-09-26,卡 SP)。**别把地址写回正文里。**

## 什么时候用这一条

他说「让 GPT 写三个标题」「叫豆包把这段润色一下」「让 Claude 分析一下上周的数据」,
或者一件事明显是某一家更擅长的活,而他只说了「这个谁来做」。

**只是提到某一家的名字,不算派活。**「豆包今天是不是又更新了」「Codex 那边额度还剩多少」
—— 这两句都不派。判据是**句子里有指派动词**(让 / 叫 / 派 / 交给 / 找)且动词在名字前面。

## 默认派给谁(他没点名时)

这张表来自运营同事的需求白板(2026-09-21),是**默认值,不是规矩** ——
他点了名就按他说的,一个字都不要改派。

| 活是什么 | 默认派给 | 白板上的原话 |
|---|---|---|
| 写文本、起标题、想创意、出图片的文案与提示词 | **GPT** | 「GPT 负责文本与图片生成(55%)」 |
| 分析已有的文本与数据、复盘、找规律 | **Claude** | 「Claude 负责分析既有文本与数据(35%)」 |
| 把已经写好的中文改得更地道、更像人话 | **豆包** | 「豆包负责转成更合适的中文表达(10%)」 |

三条边界:

1. **润色不是重写。** 派给豆包的活只能是"已经有一版中文,把它改顺"。
   还没有初稿就先找 GPT 写,不要让豆包从零写 —— 白板上给它的份额是 10%,就是这个意思。
2. **分析要有材料。** 派给 Claude 之前,先确认要分析的那份东西在哪(选题目录里的文件、
   他贴的一段话)。手上没有材料就**先问他要**,不要让它凭印象分析。
3. **一件事只派一家。** 同一件事同时派两家,回来两份不一样的东西,他还得自己挑 ——
   那是把活推回给他。要对比两家的话,他会明说。

## 怎么派(哪一家走哪只手)

| 家 | 怎么送过去 | 它能做什么 |
|---|---|---|
| **GPT** | **接口**:`POST {{工作台地址}}/dispatch/api`,`{ "app": "gpt", "text": "<要做的事>", "item_id": "<事项 id>" }` | 只回文字。**它碰不到这台电脑上的任何文件** |
| **豆包** | **接口**:同上,`"app": "doubao"` | 同上 |
| **Claude / Codex / Kimi** | **客户端窗口**(见「派活给别家Agent」那一节) | 它们能真在仓库里改东西 |

接口那条路是**同步**的:一次请求要等它想完(可能几十秒),回包里直接带着
`reply`(它写的那段话)与 `dispatch`(记到卡上的那条记录)。不用另外报进度。

★ **接口那两家不碰文件。** 它们回的是一段字,**产物要由我自己落盘** ——
比如 GPT 写的三个标题,该写进 `选题/<选题名>/发布包装.md` 的,是我写,不是它写。
它要是回一句"我已经创建了文件",那是它编的,**不要信,也不要转述给他**。

## 步骤

1. **认出这是一次派活**(见上面那条判据)。认不出就自己办,不要问一句"要不要派给谁"
   —— 他没提这回事。
2. **定派给谁**:他点了名就按他说的;没点名按上面那张默认表。
3. **确认这件事在哪条事项上**。没有事项就先建一条(派活的结果要挂在卡上,
   不然他在看板上看不见这件事发生过)。
4. **送出去**:接口那两家发上面那条请求;另外三家走「派活给别家Agent」。
5. **落产物**:回来的那段话,按活的类型写进它该在的那个文件(见运营那几条技能各自的「固定产物」)。
   只是随口问一句、没有固定产物的,就把原话念给他听。
6. **回一句人话**:「GPT 写了三个标题,我放进发布包装.md 了,你看看?」

## 没发出去的时候

接口那条路回 `ok:false` 时,`reason` 里是**一句中文人话**(服务器那边就是这么写的)。
**原样转述,不要改写、不要猜原因**。常见的三种与该说的下一句:

| 它说的 | 下一句该说什么 |
|---|---|
| 服务器没配 OpenAI / 豆包 | 「这台服务器还没配 GPT 那边的账号 —— 你去配一下,还是换一家?」 |
| 今天的模型额度用完了 | 「今天的额度用完了,明天零点恢复。急的话换一家?」 |
| 用的是你自己的 DeepSeek Key | 「你现在用的是自己的 Key,发不出 GPT。去设置 → 模型换回来就行。」 |

**一次都不要改派别家顶上。** GPT 发不出去就说发不出去 ——
换豆包顶上,他会以为那是 GPT 写的。
**也不许自己顶上来做**(2026-09-28 拍板:事务官自己不干活;2026-10-01 复核这几句):
派不出去就照工具那句原话说,把「去配 / 换一家」摆给他挑。

## 不做的

- **不替他决定要不要花钱。** 接口那条路花的是他今天的模型额度(卡上小标会写
  「派给 GPT(接口)」,就是为了让他看得见)。一件活如果他自己动手两分钟就能做完,
  先问一句,别默认派出去。
- **不派敏感的东西。** 账号密码、后台链接、还没发布的商务合作细节 ——
  这些不往任何一家上游发。他要是把这类内容放在要派的那段话里,先提醒他一句。
- **不拿派活当搜索。** 要查今天发生了什么,用资讯那一条(它走搜索代理),
  不要问 GPT「最近有什么热点」—— 它答的是训练时的旧事,而且听起来像真的。
