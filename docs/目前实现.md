## 三、一件委托现在怎么走（10-29 起）

全部入口进 `workbench-plugin/src/server/hub/`：上下文包（卡、挂着的问、附件）→ 模型按命令表出命令（19 条：dispatch / reassign / supplement / rename / cancel / move_status / goal_* / note / user_layer_fix / remember / feedback / voice / ask / confirm / chat / verify）→ 护栏（取消 / 丢弃 / 风险 → 问一句）→ 执行 → 回话 + say 账。入口只按受信身份定（desktop / phone / call），不再按文字分流。快路径只剩两条：挂着的问按选项原话答、一句只有一种读法的「好 / 先别」。

一件委托一张执行记录（`taskExecution.ts` 纯函数：阶段 + 下一动作 + 版本；`taskExecutionStore.ts` 独占写，挂在卡上 `execution` 一格）。派发口 `dispatchRun.ts` 派前先写账（写不上不起子进程）、换手只按记录里的候选表、结果不明记 reconciling 不开第二作者、重启从记录恢复换手待发。核验交付 `taskExecutionDelivery.ts` + `dispatchVerify.ts`：凡交回都核（CLI / 窗口 / 接口 / 事务官自办同一钩）、缺验收从委托提取默认条件写卡再核、按产物核（文件 / diff / 代跑测试）、核不了带 wakeAt 定时再核、不过退修走派发口、重派被闸挡下卡回「等确认」不挂 doing、「按通过结掉」= 人判通过、重启接着核、用户层热装 ok 才记交付。

## 七、怎么跑起来

- **用户**：按 README，双击 macOS 安装包与 Android 安装包；不以命令行为入口。
- **开发插件**：本仓库与 `deepseek-harness`（DSH 上游，锁在 `dsh-v0.1.7-rc.2`，不跟随升级）放同一父目录；上游各包的 `main` / `types` 指向构建产物 `lib/`，所以先在上游里安装并构建。然后在 `workbench-plugin/`：`pnpm install && pnpm test && pnpm typecheck && pnpm build`。只检出本仓库装不上依赖，是最常见的第一道坎。
- **挑用例跑**：`pnpm test -- <files>` 不过滤，用 `npx vitest run --maxWorkers 1 <files>`。
- **类型检查前先装手机端依赖**：插件的 `pnpm typecheck` 连带检查 `butler-app/src/api/tokenStore.ts`，`butler-app/` 没 `pnpm install` 时会报 3 条找不到 `@capacitor/preferences`，不是代码错。整包里 `dev/acceptance-three-entrances/phoneRoomControl.test.ts` 要 `channel-worker/` 装过依赖（`@livekit/rtc-node`）。
- **闸**（合并前）：`npx vitest run --maxWorkers 1 <改到的用例> tests/hub-*.test.ts` → `npx tsc --noEmit` → `node scripts/gen-bundled-skills.mjs && npx tsdown && node scripts/copy-starter-layer.mjs && node scripts/copy-archify-assets.mjs`；再跑整包对照 25 个基线红。
- **意图回归集**：`node dev/intent-regression/run.mjs --entrance desktop --repeat 3`，报告按真跑提交。
- **其他目录**：各自独立工具链，互不 import。手机端要 JDK 21 与 Android SDK（`io.livekit:livekit-android:2.29.0`）；壳与安装器要 Xcode；`butler-server` 用 Node 内置 `node:sqlite`；`channel-worker` 要 Node ≥ 24。
- **发版**：只在 main 上，`bash deploy/publish-update.sh --gate-settle 30 --notes "…"`：先把这一版装到本机、等 8791 回新版本号与 `/state` 200、120 秒 CPU 线、回归门，过了才 rsync 到服务器；缺省只发插件与启动脚本。版本号提交只改 `workbench-plugin/package.json`。合并后先 `git merge-base --is-ancestor` 核过再升版本号。
- **对外连接都能配**：插件 `~/.dsh/workbench/endpoints.json`（`aiboo_url` / `aihot_url` / `update_manifest_url`，写 `"off"` 关掉）或 `model.json` 的 `relay_url`；事务官后端 `butler.json` 的 `endpoints`；展示台构建时 `VITE_AIBOO_BASE_URL`。中转与更新清单地址构建时注入，没注入 = 零服务器。
- **重启 8791**：`launchctl kickstart -k gui/$(id -u)/ai.deepseek.dsh`（8791 与 3080 是同一个 node 进程）。**抓 CPU 剖面**：`kill -USR1 <pid>` 后 `node workbench-plugin/scripts/profile-loopback-cpu.mjs 9229 10`。

## 八、已知的坑

- `~/.dsh/workbench` 下约五十个 json 的权威来源各不相同，别把 `model.json`、`sentinel.json` 当缓存。
- 全插件没有一处 fsync；`tasks.json` 读坏会回空看板，下一次写就整块覆盖。
- 审批 id 是内存里的 randomUUID，没有过期、不记答复者；重启后挂着的问全丢（可靠执行第二批要收）。
- DSH ACP：权限请求没有超时；只有 allow-once 算批准；MCP 工具调用 60 秒超时不可配；会话创建时定权限档，resume 保持原档。
- 微信、企业微信联系人不走捎话接口（有一道门），别去掉。
- Android 17 起本地网络要运行时权限，局域网直连 8791 与 mDNS 要补授权。
- 写板上状态的接口（`/butler/say`、`/task/*`、`/collab/goal/update`、`/layout`）认受信身份：只有本人、事务官、工作台自己；无身份写请求 403 是设计，不冒用 `x-workbench-actor`。
- 在软链 `node_modules` 的工作树里不要跑 `pnpm`（会要求重装并清目录）；发版只从主检出跑。
- `git merge --ff-only … | tail` 这类管道会吞掉失败：合并后核祖先再升版本号（10-29 出过一次空版）。
- 发版前 `git status workbench-plugin/dev/intent-regression/`：工作副本被跑过会盖住提交的报告。
