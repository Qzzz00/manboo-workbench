# 设计:事务官的完整引导流程 v2(2026-09-11,按 维护者 三条修订;待拍板)

> 称呼改了:**「总管」→「事务官」**(维护者 2026-09-11)。本文起用新名;历史文档不改。

## 一、维护者 定的三条(原话要点)
1. **形式**:下载手机 App,在手机上和 AI 对话——主机不一定有麦克风,收音是问题,打字不够自然;引导本身就是一个梳理的过程。电脑上也支持文字交互。
   引导应该出现在「电脑装好、**登录了同一个账号**」之后——参考 UGreen NAS 那种局域网协作的流程。
2. **流程**:两种——**从零开始**(没有项目,从一个新点子起)/ **已有项目**(逐步开始)。
3. **顺序**:先简单自我介绍(「我是你的专属事务官」)→ 问称呼 → 分岔:已有项目还是新点子。两套流程截然不同;
   已有项目时**两件事并行**:一边授权去读电脑里的仓库与文件,一边和用户聊——效率更高。
   梳理与理解项目的过程**不是预设好的问题清单**,而是记录目标、由模型围绕**现状、愿景、各种细节**展开;然后是授权、使用习惯与偏好(含喜欢的歌手/曲风,用于构建歌单)等。

## 二、设备与账号:先配对,后账号(参考 UGreen NAS 的做法,做减法)
UGreen NAS 的流程是:App 在局域网自动发现设备 → 登同一个账号 → 绑定 → 之后走中继远程访问。我们现在没有账号系统,分两步走:
- **第一步(本期)**:**配对**。电脑上装好工作台后,设置里显示一个 6 位配对码 + 二维码(内含局域网/热点地址与码);手机 App 首次打开先找设备:同一局域网 mDNS 自动发现工作台,或扫码/输码。配对成功双方各存一个设备令牌(手机存工作台地址 + 令牌;工作台在 `~/.dsh/workbench/devices.json` 记手机),之后所有请求带令牌,8791 对非回环的写接口从「一律 403」改成「持有效设备令牌可写」。
- **第二步(以后)**:账号。要走公网中继、多设备、多人时再上;届时「同一账号」= 令牌由账号签发,流程不变。
- 引导的触发点:**手机 App 配对成功的那一刻**,事务官在手机上开口。电脑端的事项收件箱只作为文字备胎,不重复触发。
- 现状:display-client 有一个固定配对码 `ben1`(展示台用),不是这套;需要新做。

## 三、流程总览
```
配对成功
  └─ ① 自我介绍 + 问称呼(30 秒)
       └─ ② 分岔:「你现在是已经有在做的事,还是想从一个新点子开始?」(中性,不提项目 / 账号)
       └─ ①′ 布局:顺着他刚说的事问「这件事更像做产品研发,还是做自媒体运营?」(2026-09-23 起排在分岔之后)
            ├─ 运营(ops):②′ 账号(已有 = 录一个号;新点子 = 一个还没开的号),不扫仓库
            ├─ A 已有项目(并行两线)
            │     A1 授权线:逐项请求读权限 → 拿到即后台扫描仓库/文件,把看到的喂给对话线
            │     A2 对话线:开放式访谈,围绕现状 / 愿景 / 细节,记录目标
            └─ B 从零开始
                  B1 点子访谈:一句话 / 想解决谁的什么问题 / 现在手上有什么 / 第一步想做什么
                  B2 立项:建项目文件与第一个事项,不扫描任何目录
  └─ ③ 授权补全(A 已在线做,B 在此时做;写权限、写接口默认否)
  └─ ④ 使用习惯与偏好(含音乐口味 → 歌单)
  └─ ④′ 对话预期与状态(选人设)
  └─ ④″ 给事务官取名
  └─ ⑤ 收尾:复述、拿不准、汇报时间与下班例程、第一条事项建议
```

## 四、各步细则
### ① 开场白(维护者 2026-09-11 亲笔,一字不改)
> 你好,很高兴认识你,我是你的专属事务官。我能够帮助你更轻松、更有条理的经营你的事业,为了后面的工作能顺利开展,我需要对你和你正在做的事有一些了解,首先,你希望我怎么称呼你?

写 `docs/记忆/用户-维护者.md`「自述」段(用户口述、事务官记录)。

### ② 分岔
一句话问,两个选项;答不清就默认 A(扫描根里有仓库)或 B(空)。
2026-09-23 起它紧跟在称呼之后、布局之前(维护者第二轮真机:「为什么一开始是布局而不是从新点子或已有项目,这反了啊」),
问的时候还不知道他做产品还是做运营,所以用中性的「已经有在做的事」,不说"项目"也不说"账号"。
布局那一问接在后面,顺着这件事问;②′ 等布局定了再按模板分产品线 / 运营线。见决策记录 2026-09-23「引导先问分岔」。

### A. 已有项目——并行两线
**A1 授权线**(逐项、可以/不可以、说清用途):读三个扫描根与指定目录;读各家会话的状态与标题(不读正文);读工作台状态。
拿到哪项就立刻在后台做哪项:扫仓库、读 README/AGENTS/docs、看提交与最近改动、看任务板。结果**不打断对话**,以「我刚看到…」的方式在对话线里自然带出。
**A2 对话线——开放式访谈,不是问卷**。事务官手里只有一份「**要弄清的东西**」清单(不是要问的问题),按对话自然走,问过的不再问:
| 要弄清 | 从对话拿 | 从仓库拿(A1 喂进来) |
|---|---|---|
| 这个项目是什么、给谁用 | 用户一句话 | README / 项目介绍 |
| 愿景:做成什么样算成 | 用户说 | PRD / BP |
| 现状:到哪了、卡在哪 | 用户说 | 最近提交、未提交、看板 |
| 细节:关键决定、不能碰的、合作的人/Agent | 用户说 | 决策记录、AGENTS.md |
| 下一步与截止日 | 用户说 | 任务板、DDL |
每弄清一项就写进 `docs/记忆/项目/<名>.md` 对应字段(当场答 = 已拍板),一个项目一次 commit;拿不准的写「拿不准」。
多项目时先问「先聊哪个」,其余「稍后」记进度。**仓库看到的与用户说的矛盾时,事务官指出来,以用户为准**。

### B. 从零开始
B1 访谈四问顺着聊:「一句话说它是什么」「想解决谁的什么问题」「现在手上有什么(想法/素材/人)」「第一步想做什么」。
B2 立项:建 `docs/记忆/项目/<名>.md`(阶段=市场调研或项目策划,由用户定)、建第一个事项(方向=我交给事务官);**不扫描任何目录**,不装东西。

### ③ 授权补全
A 线已问过读权限(**已答的这一段不再问**,2026-09-23);此处补写权限:往事务官工作目录的记忆文件夹 `docs/记忆/` 写、每段本地存一个版本(git commit,**不推远端**;对他说「只在这台电脑上」,不说仓库 / 提交 / 推上去)(问);调工作台写接口(**默认不可以**,单独一问);删文件/改代码/凭据(永不请求,主动声明)。写 `docs/记忆/授权.md`,插件校验。

### ④ 使用习惯与偏好(聊着记,不逐条问)
- 工作节奏:一天几段、几点开工收工、什么时候不想被打扰。
- 汇报偏好:早上先汇报再干活?变化到什么程度才叫你?
- 语音还是文字、称呼语气、要不要 Live2D 形象说话。
- **音乐口味**:喜欢的歌手、曲风、工作时听什么、不想听什么 → 写 `用户-维护者.md`「偏好」段,供 AIDJ 建歌单(本机后端搬 dj 模块后接上)。
- 其它自述(家里/身体/近期安排里与工作相关的)——只记工作需要的,不追问私事。

### ④′ 对话预期与状态(项目了解完之后,维护者 2026-09-11 加,很重要)
事务官问:「接下来的日子里,你希望我用什么样的方式和状态跟你对话?」给几个选项让用户挑,也可以混搭或自己描述。
候选人设收成 **三个**(维护者 2026-09-11:九个太多,且每个要配专属 Live2D 形象;前几个区别不大)。三个之间的差别要一眼能分,各配一个 Live2D 形象供挑:
| 编号 | 人设 | 一句自述 | 示例(同一件事:某任务卡三天没动,周五要交) | Live2D 形象 |
|---|---|---|---|---|
| A | **沉稳** | 话少,先结论后理由,不闲聊,只在必要时开口 | 「X 三天没动,截止日周五。要不要挪到今天?」 | 待配(干练、冷色) |
| B | **周到** | 主动、细致,会顺手关心你的状态,话稍多 | 「X 三天没动了,周五要交;你这两天会议多,排到明早第一件?材料我先理好。」 | 待配(温和、暖色) |
| C | **傲娇** | 嘴硬心软:嘴上嫌弃、手上早帮你做好;不邀功,被夸会别扭 | 「哼,X 三天没碰,周五要交我可不背锅。……材料摆好了,不是特意的。」 | 待配(俏皮、有小表情) |
傲娇在四种场景下的口吻(供事务官照样子写,不是照抄):
- 提醒:「X 三天没动了。周五要交。……我又不是提醒你,只是路过。」
- 做完了:「材料理好了,放你桌上了。别谢我,顺手的事。」
- 出错/赶不上(**不耍宝,先说事**):「Y 赶不上周五了,差两天。我不绕弯子:今天砍范围,还是往后挪?你定。」
- 被夸:「……知道了。下次别说这种话。」
其余差异做成**两个旋钮**,不再另立人设:**直言度**(委婉 ↔ 说破风险、会反驳)、**话量**(只答不问 ↔ 主动提醒)。任何人设都可以调。
俏皮类的规矩:**包装可以俏皮,内容不能打折**——时间、数字、风险照实说;不在坏消息(出错、赶不上)上耍宝。
写 `docs/记忆/用户-维护者.md`「偏好·对话方式」+ `~/.dsh/AGENTS.md` 的语气段(由统筹会话/事务官按选择更新;AGENTS.md 对事务官只读,所以这一条由用户确认后统筹会话写)。

### ④″ 给事务官取名
「最后,给我取个名字吧——以后你这么叫我,我也这么自称。」
用户答后事务官复述一遍确认;写 `~/.dsh/AGENTS.md` 首行与 `用户-维护者.md`;可随时改。没想好就先叫「事务官」。

### ⑤ 收尾
复述(称呼、重心、项目确认了几个、授权了什么、偏好);列「拿不准」;定汇报时间与下班例程时刻;提第一条事项建议(只提议);commit `chore(记忆): 入职·收尾`;说「以后我先开口」。
